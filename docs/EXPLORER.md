# Диски в Проводнике — Cloudloom Maple для Windows

Функция доступна в Cloudloom для Windows. Maple добавляет маленькую кнопку рядом с каждым профилем и официальный WinFsp-установщик внутри приложения. Это нативное обновление, доступное Kestrel/Linden при запуске, а не обновление live-каталога.

## Как подключить

Для portable-сборки Windows 10/11 x64: распакуйте ZIP целиком в новую папку, закройте ранее запущенный Cloudloom и откройте `cloudloom.exe`. Папка `resources` должна оставаться рядом; нужен WebView2 Runtime. Если старая копия ещё работает, защита от второго экземпляра откроет её окно вместо новой сборки. Данные профилей используются из обычного пользовательского каталога Cloudloom. Для автоматических обновлений рекомендуется установщик.

1. Подключите профиль обычным способом в Cloudloom.
2. Нажмите маленький значок диска рядом с профилем: он откроет настройки именно этого профиля. Общая кнопка **Диски в Проводнике** тоже остаётся доступна.
3. Если WinFsp отсутствует, нажмите **Установить WinFsp** внутри Cloudloom и подтвердите запуск официального установщика. MSI уже включён в Windows-пакет, проверяется по SHA256 и цифровой подписи; отдельно скачивать его не нужно. Windows запросит права администратора, а установщик покажет лицензию и параметры. Установка не скрытая, без принудительной перезагрузки. Если Windows запросила перезагрузку, выполните её до подключения. Сам Cloudloom запускайте без повышения прав, как Проводник. Уже установленный WinFsp автоматически не заменяется; отмена установки не мешает обычной работе приложения.
4. Выберите профиль, свободную букву D–Z, название до 32 символов и значок сервиса. Новые подключения по умолчанию разрешают чтение и запись. Для защиты от изменений включите **Только чтение**. Сохранённые подключения сохраняют выбранный ранее режим. У подключённого диска режим явно указан; кнопка **Включить запись** безопасно переподключает диск после подтверждения и проверки очереди.
5. Нажмите **Подключить диск**, затем **Открыть Проводник**.

В режиме записи поддерживаются обычные файловые операции в пределах разрешений сервиса: чтение, копирование в обе стороны, создание папок, переименование и удаление. Удаление через Проводник действует на облако; отдельного подтверждения Cloudloom для каждой операции нет. Корзина и восстановление зависят от провайдера.

Название локальное, не меняет имя аккаунта. Для смены имени, буквы, значка или режима отключите диск, измените настройки и подключите его снова. Значки Google Drive/Dropbox используют геометрические знаки; остальные сервисы — цветные буквенные значки. Иконки встроены в приложение, не запрашиваются с сайтов аккаунтов. Windows может кэшировать оформление до обновления окна Проводника.

Настройка **Подключать при запуске Cloudloom** действует после проверки обновлений, пока запущено приложение; это не служба Windows и не запуск приложения при входе в ОС. Ручное отключение диска выключает его автоподключение. При занятой букве или ошибке авторизации другой диск не заменяется; ошибка показывается в настройках.

## Безопасное отключение и кэш

Закройте файлы этого диска в редакторах и других программах, дождитесь отправки изменений, затем отключите диск в Cloudloom. Обычное закрытие окна приложения блокируется, пока есть подключённые диски, и открывает их настройки.

Каждый профиль имеет отдельный постоянный VFS-кэш. Чтение происходит по мере обращения, запись сначала идёт в кэш, затем отправляется после закрытия файла. Целевой максимум кэша — 10 ГиБ, резерв свободного пространства — 1 ГиБ; это мягкие ограничения: открытые и неотправленные файлы могут превышать их. Кэш **не зашифрован Cloudloom** и может содержать имена и содержимое файлов; используйте защиту диска Windows для конфиденциальных данных. Это не полная офлайн-копия.

Перед отключением проверяются очередь загрузки, ошибки и dirty-метаданные, включая открытые файлы с изменениями, ещё не попавшие в очередь. При неизвестном состоянии отключение блокируется. Проверка не является атомарной блокировкой внешних программ: не открывайте и не изменяйте новые файлы во время отключения. Поздние изменения сохраняются в кэше и требуют повторного подключения с записью.

При аварии/принудительном завершении Windows Job Object останавливает процесс диска. Оставшиеся на диске изменения не удаляются и восстанавливаются при повторном подключении того же профиля с записью. Это не гарантирует сохранность данных, которые другая программа ещё не записала, или сохранность при сбое диска/электропитания. Не удаляйте кэш вручную при неотправленных изменениях. Профиль нельзя удалить, если диск подключён или кэш содержит такие изменения.

Cloudloom изменяет оформление только в пользовательском разделе реестра, не требует администратора и не перезаписывает существующие настройки чужого диска. Созданные значения помечаются владельцем и удаляются при отключении; пользовательские изменения и посторонние значения сохраняются. После аварии оформление восстанавливается при следующем запуске, только если буква свободна.

## Ограничения

### Папка буфера передачи

В настройках каждого профиля есть поле **Папка буфера передачи** и кнопка **Выбрать папку…**. Можно выбрать существующую доступную для записи папку на локальном или внешнем накопителе. Cloudloom создаёт внутри `Cloudloom-buffer/<id-профиля>`; там находятся VFS-кэш диска и временные загрузки Delivery. Папка по умолчанию остаётся прежней для совместимости со старыми подключениями. Обычные передачи внутри Cloudloom используют исходный/целевой файл напрямую, а не промежуточную полную копию.

Сначала отключите диск и дождитесь отправки файлов. Если в прежнем буфере есть dirty-метаданные, ошибки чтения или недоступен накопитель, смена расположения блокируется. Подключите прежний буфер с записью и завершите отправку. Старые чистые файлы не переносятся и не удаляются автоматически. Сетевые и облачные диски в качестве буфера не поддерживаются. Если внешний накопитель отключён, Cloudloom покажет ошибку и не подменит его буфером на C:.

- Только Windows x64. Mac-приложение продолжает работать как раньше, без подключения в Finder.
- Профили rclone, включая WebDAV, Google Drive, OneDrive, S3 и локальные папки. Возможности и стоимость операций зависят от провайдера.
- **Delivery с транспортом SFTPGo user API подключается с сохранённым входом.** Встроенный локальный адаптер переводит операции диска в пользовательский API. Отдельный адрес WebDAV не требуется. Адаптер слушает только 127.0.0.1, требует случайный токен на каждый сеанс и закрывается с диском. Пароль сервера остаётся внутри Cloudloom. Чтение поддерживает диапазоны байтов, запись проходит через временный файл и очередь rclone; для записи нужно дополнительное свободное место на компьютере. При режиме «Только чтение» адаптер также запрещает операции изменения. Перемещение поверх существующего элемента отклоняется с сохранением обоих файлов.
- Нет атомарного согласования одновременных изменений между Проводником, Cloudloom и другими клиентами. Не редактируйте один файл одновременно в нескольких местах. Программам с требованиями к локальным блокировкам/базам данных сетевой диск может не подойти.
- Ключи, пароли и локальный RC API не передаются в WebView. Управление движком использует случайный loopback-порт и случайный пароль, без перенаправлений, прокси и доступа из сети.

## Проверка

Обычные frontend/Rust-тесты не требуют установки драйвера. Отдельный Windows-тест с установленным WinFsp создаёт временную локальную папку, подключает свободную букву и проверяет чтение, запись, папки, переименование, удаление, запрет записи, смену имени, выбранный значок через Windows Shell и блокировку отключения при открытой dirty-записи. Также проверяются запрет неавторизованного RC-запроса, остановка процесса диска при завершении родителя и восстановление диска при следующем старте. Новый Shell-клиент читает новое имя; уже открытые Shell-клиенты могут кэшировать старое название. Рабочие облака не используются. После теста временный диск и его оформление убираются.

```powershell
$env:CLOUDLOOM_TEST_MOUNTS='1'
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib real_windows_mount_read_write_readonly_and_appearance -- --nocapture
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib explorer_delivery_bridge_real_rclone_roundtrip -- --nocapture
```

Второй тест запускает изолированный SFTPGo-совместимый тестовый API, настоящий rclone и адаптер Delivery. Проверяет список с кириллицей, пробелами, `%` и XML-символами, чтение диапазонов, загрузку и перезапись, перенос, удаление, запрет стороннего Destination/Origin и неавторизованного входа. С `CLOUDLOOM_TEST_MOUNTS=1` дополнительно подключает настоящий временный диск WinFsp, проверяет операции Проводника, чтение ранее не кэшированного файла и режим только чтения. Без флага проверяется адаптер без диска и без драйвера.

Основание реализации: [rclone mount](https://rclone.org/commands/rclone_mount/), [rclone RC](https://rclone.org/rc/), [WinFsp](https://winfsp.dev/rel/), [оформление дисков Windows](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-assign-a-custom-icon-and-label-to-a-drive-letter).
